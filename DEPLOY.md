# Deploying to Vercel (single project)

The app deploys as **one Vercel project**: the FastAPI backend runs as a Python
serverless function and also serves the built React frontend from the same
origin, so the browser calls `/api/...` with no CORS hop.

- Storage: **Neon Postgres** (documents + parsed chunks as JSONB)
- Answer generation: the **chat gateway** at `CHAT_API_URL` (RAG-by-LLM)
- No local filesystem, no embeddings model, no FAISS — fits the serverless function

## 1. Create a Neon database

Add Neon from the Vercel dashboard: **Storage → Create → Neon** (or use an
existing Neon project and paste its connection string). This gives you a
`DATABASE_URL`. The `documents` table is created automatically on first boot
(also in `backend/schema.sql` if you want to run it by hand).

## 2. Import the project

Point Vercel at this repository and set the **Root Directory to `backend`**.
Vercel detects FastAPI (instance `app` in `app/main.py`) and builds it for the
Python runtime. The frontend build runs via the `build` script in
`backend/pyproject.toml`, which compiles `frontend/` into `backend/public/`.

## 3. Environment variables

Set these in **Project → Settings → Environment Variables**:

| Variable | Required | Value |
|---|---|---|
| `DATABASE_URL` | yes | Neon connection string (auto-set if you added Neon via the dashboard) |
| `CHAT_API_URL` | no | Defaults to `https://ai-cloud-server-delta.vercel.app/api/chat` |
| `CHAT_MODEL` | no | Defaults to `auto` |
| `CHAT_API_KEY` | no | Only if your gateway requires a bearer token |
| `CORS_ORIGINS` | no | Not needed for same-origin. Set only if a separate frontend calls the API. |

Leave `VITE_API_URL` **unset** in production so the frontend uses same-origin
`/api/...`. (It is set to `http://localhost:8000` in `frontend/.env.local` for
local dev only.)

## 4. Deploy

Push to your connected branch, or run `vercel --prod` from `backend/`.
Vercel installs `backend/requirements.txt`, runs the frontend build, and ships
the function. `maxDuration` is 60s (`backend/vercel.json`) to cover LLM calls.

## Local development

Backend:
```
cd backend
python -m venv .venv && .venv/bin/pip install -r requirements.txt
DATABASE_URL=... .venv/bin/uvicorn app.main:app --reload   # http://localhost:8000
```

Frontend (separate terminal):
```
cd frontend
npm install && npm run dev                                  # http://localhost:5173
```
`frontend/.env.local` points the dev server at the local backend.

## Verifying the pipeline

`backend/tests/test_rag_pipeline.py` ingests a tiny PDF into Postgres, checks
retrieval, and confirms the gateway returns a grounded answer:
```
cd backend
DATABASE_URL=... .venv/bin/python tests/test_rag_pipeline.py
```

## Notes / tradeoffs

- This is no longer the fully-offline app from the original README: PDF text is
  sent to the chat gateway for answering, and stored in cloud Postgres.
- The 300-DPI page-image gallery was removed (not feasible in a serverless
  function). Answers cite page numbers instead of page images.
- Answers are generated by the LLM from retrieved context, not returned verbatim
  from the PDF.
